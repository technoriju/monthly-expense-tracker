# Monthly Expense Tracker

Offline-first income and expense tracker for Android and iOS. Add entries by hand or by voice
(English, Bengali, Hindi), set monthly budgets, see reports, and back up / restore your data as
a file. There is no account, no server and no analytics: data is stored in a local SQLite
database on the device.

- **Stack:** Expo SDK 58 · React Native 0.88 · TypeScript (strict) · Expo Router · expo-sqlite ·
  Zustand · React Hook Form + Zod · i18next · react-native-svg
- **UI languages:** English, Bengali, Hindi (other Indian languages are listed but not yet
  translated). Voice language is a separate setting from UI language.
- **Docs:** [Architecture](docs/ARCHITECTURE.md) · [Roadmap](docs/ROADMAP.md) ·
  [Design](docs/design.md) · [Testing](docs/TESTING.md) ·
  [Release checklist](docs/RELEASE_CHECKLIST.md) · [Store listing](docs/STORE_LISTING.md) ·
  [Privacy policy draft](docs/PRIVACY_POLICY.md)

## Requirements

- Node.js 22+ (tests use Node's built-in `node:sqlite`)
- Android: Android SDK + JDK 17, a device or emulator
- iOS: macOS with Xcode (or EAS cloud builds)

## Setup

```bash
npm install
```

Add dependencies only with `npx expo install <package>` so versions match SDK 58.

## Run (development build required)

The app uses native modules that **Expo Go does not include** (`expo-sqlite`,
`expo-speech-recognition`), so it must run as a development build:

```bash
npx expo run:android      # build, install and start on a connected device/emulator
npx expo run:ios          # macOS only
npx expo start            # Metro only, for an already installed development build
```

## Verify

```bash
npx tsc --noEmit          # typecheck
npx expo lint             # ESLint
npx jest                  # unit, service, repository (real SQL) and component tests
npx expo install --check  # dependency versions match the SDK
```

See [docs/TESTING.md](docs/TESTING.md) for what the tests cover and the manual device checklist.

## Voice entry and speech recognition

Voice entry uses the device's speech recognizer (Google on Android, Apple on iOS):

- It runs offline only when the language's offline pack is installed on the device; otherwise
  the OS service may send audio over the internet, under that provider's privacy policy.
- Availability depends on the device: devices without the Google app/speech service, or
  without support for the chosen locale, show an "unavailable" state. Manual entry always works.
- Recognized text always goes to a Review screen; nothing is saved without the user's confirmation.

## Backup and restore

- **Backup** writes a versioned JSON file (all categories, transactions, budgets and
  preferences) that you share or save to a folder you pick. The file is **not encrypted**.
- **Restore** validates the whole file first (format, version, amounts, dates, references,
  size) and then replaces all data in one database transaction — a failure changes nothing.
- **CSV export** of a period's transactions is available from Reports and Settings.

## Production builds

Release configuration lives in `app.json` and `eas.json` (profiles `development`, `preview`,
`production`). Store builds are made with EAS:

```bash
npx eas-cli login
npx eas-cli init                                   # links the project (adds owner/projectId)
npx eas-cli build --platform android --profile production
npx eas-cli build --platform ios --profile production
```

The full procedure, versioning and signing notes are in
[docs/RELEASE_CHECKLIST.md](docs/RELEASE_CHECKLIST.md).

## Android build troubleshooting (Windows)

`android/` is generated by `npx expo prebuild` and is gitignored — never edit it by hand.
When a native build fails with stale-cache errors, after adding a native package, or after
moving the project folder (CMake caches store absolute paths):

```bash
cd android && ./gradlew --stop && cd ..   # stop Gradle daemons (skip if android/ is missing)
npm run clean:android                      # delete android/ and node_modules/*/android/{build,.cxx}
npx expo prebuild --platform android       # regenerate android/ from app.json + config plugins
npx expo run:android                       # rebuild and install the development build
```

On Windows PowerShell use `cd android; .\gradlew --stop; cd ..` for the first line.

The `postinstall` script (`scripts/patch-windows-paths.mjs`) works around the Windows
260-character path limit for native C++ builds; it does nothing on macOS/Linux. If a native
build still fails with `ninja: error: mkdir(...)`, move the project to a short path such as
`D:\met` and clear the cache as above.
